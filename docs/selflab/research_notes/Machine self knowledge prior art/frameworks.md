## 1. NNsight 0.7.0 (plus 0.8.0rc1) and NDIF: API, hands-on verification, source-capture constraint, remote execution

### Takeaway
NNsight 0.7.0 reproduced every NeuralScope primitive bit-exactly against native hooks on Qwen2.5-0.5B-Instruct, with no measurable overhead: residual capture, zero-ablation through the o_proj-input slice, cross-prompt residual patching, gradients with respect to an activation, steered multi-token generation, batched edit sets, and resume-from-depth via `Envoy.skip`. It is the strongest candidate backend. It has sharp edges, though. In 0.7.0, pre-tokenized tensor inputs in a second or later `invoke` silently receive an all-zero attention mask, producing wrong outputs (fixed in 0.8.0rc1). Traces need real source code (they fail from stdin or an `exec`'d string). Values cross invoke boundaries only through `tracer.barrier()`. `model.generate()` inherits the checkpoint's `generation_config` (for Qwen2.5 that means `repetition_penalty=1.1`). NDIF is free for research and needs an API key. On 2026-09-30 it had 21 HOT deployments (Llama-3.1/3.2/3.3, Gemma-2, Qwen2.5-7B to 72B). Qwen2.5-0.5B-Instruct and the Qwen3 models appear only as COLD registry entries.

**API surface in 0.7.0 (code-verified in `$SP/nnsight`)**
- Tracing: `with model.trace(inputs): ...`. `Envoy.output` and `.input` (first positional argument) and `.inputs` read and write module values. `.save()` is mounted on every object when `CONFIG.APP.PYMOUNT=True` (default), with `nnsight.save(obj)` as the alternative (`$SP/nnsight/config.yaml`, `schema/config.py`, `intervention/tracing/globals.py`) (code-verified).
- Public tracer and envoy methods: `tracer.invoke()`, `tracer.stop()`, `tracer.iter[...]`, `tracer.all()` (equal to `iter[:]`), `tracer.next()`, `tracer.cache(modules, device, dtype, detach, include_output, include_inputs)`, `tracer.barrier(n)`, `tracer.result`; `Envoy.source`, `.trace`, `.scan`, `.edit(inplace=)`, `.export_edits`, `.session`, `.skip(replacement)` (`intervention/tracing/tracer.py:513-662`, `intervention/envoy.py:216-500`) (code-verified). `model.iter/all/next` are deprecated in favour of `tracer.*` (`envoy.py:435-465`) (code-verified).
- Gradients: `with loss.backward(): g = h.grad.save()` runs an interleaved backward (`BackwardsTracer`, `intervention/tracing/backwards.py`). Inside a backwards tracer only `.grad` may be requested (code-verified).
- Generation: `with model.generate(x, max_new_tokens=N) as tracer: for step in tracer.iter[:]: ...`. Slices, single indices and lists (`iter[0]`, `iter[1:3]`, `iter[[0,2,4]]`) target specific decode steps (`intervention/tracing/iterator.py` docstring) (code-verified). The for-loop form was new in 0.6 (the `with tracer.iter[...]` block form is deprecated) ([nnsight 0.6 blog](https://nnsight.net/blog/2026/02/26/introducing-nnsight-06/)) (docs).
- Model classes: `LanguageModel` (subclass of `TransformersModel` in `modeling/transformers.py`), `VisionLanguageModel`, `DiffusionModel`, plus a vLLM integration (`modeling/vllm/`) (code-verified). The 0.6 changes also include serialization by value for remote runs, trace caching per call site, and faster traces: empty trace 1,196 µs to 308 µs; per-intervention cost about 42 µs to about 34 µs ([nnsight 0.6 blog](https://nnsight.net/blog/2026/02/26/introducing-nnsight-06/)) (docs).
- The vLLM integration has 13 documented gaps versus HF (`$SP/nnsight/modeling/vllm/intervention-gaps/REPORT.md`): no gradients (vLLM's `inference_mode`), no attention weights (PagedAttention), a flat `[total_tokens, hidden]` layout, merged `qkv_proj`/`gate_up_proj` (no per-projection access), a dual residual stream, and `skip()` crashing the engine ("EngineDeadError — unrecoverable") (code-verified).

**Hands-on results (ran it; scripts `$W/test_nnsight.py`, `test_nnsight2-5.py`, `test_nnsight_source.py`; results `$W/test_nnsight_results.json`)**
- (1) Residual capture at all layers: `model.model.layers[l].output` is a tensor in transformers 5.17 (decoder layers return a tensor, not a tuple). All 24 layer outputs matched the native-hook reference exactly (mad 0.0; via nnterp's accessor, which is the same nnsight `.output`). `tracer.cache(modules=[layers...])` returned entries keyed `model.model.layers.N` with `.output`, `.input` and `.inputs`, and layer 0 was exact (0.206 s) (ran it).
- (2) Zero-ablating head 3 of layer 10 via `model.model.layers[10].self_attn.o_proj.input[:, :, 192:256] = 0`: logits bit-identical to the native pre-hook reference (mad 0.0). 0.185 s versus 0.199 s for the plain hooked forward (ran it).
- (3) Residual patch from prompt A into prompt B (layer 8 output, position 3), done as two traces: mad 0.0 versus reference, 0.382 s for both traces (ran it). As one trace with two invokes it requires `tracer.barrier(2)`, and was then exact (mad 0.0). Without the barrier the second invoke raised `NameError: name 'v' is not defined` (ran it). This matches the documented rule: "Both invokes touch `wte.output`; without the barrier the second worker would try to swap in `embeddings` before the first had bound the name — NameError" ([NNsight.md §6.7](https://github.com/ndif-team/nnsight/blob/main/NNsight.md)) (docs).
- (4) Gradient of logit[" Paris"] at the last position with respect to the layer-12 output, via `with loss.backward(): g = h.grad.save()`: mad 0.0 versus `retain_grad` on native hooks. 2.10 s, identical to the reference's 2.10 s, both using a full `.backward()` that also fills parameter grads (ran it).
- (5) Intervention during generation: adding a fixed random vector (norm about 120) to the layer-6 output at every step for 8 new tokens (`for step in tracer.iter[:]` and `for step in tracer.all()`) was token-identical to HF `generate()` with the same hook. 0.94 s versus 0.88 s (ran it).
- (6) Generation determinism pitfall: HF `generate(do_sample=False)`, and therefore nnsight's `.generate()`, still applies the checkpoint's `generation_config`. For Qwen2.5-0.5B-Instruct that includes `"repetition_penalty": 1.1` (`~/.cache/huggingface/.../generation_config.json`). As a result, unsteered HF greedy output (" Paris. It was founded in 7") differs from pure argmax greedy (" Paris. It is the largest city in"), which is what NeuralScope's own loop, TransformerLens and interp-engine produce (ran it). With `repetition_penalty=1.0` passed, nnsight generation matched a NeuralScope-style loop token for token (ran it, `test_nnsight5.py`).
- (7) Batched edit sets: one manual batch of 14 rows, where row h zeroes head h (`x = o_proj.input; x[h, :, slice_h] = 0`), was exact (mad 0.0) at 0.48 s versus 0.50 s for the native equivalent (ran it). The same with 14 `tracer.invoke(...)` blocks (list-of-int inputs) was exact, at 0.56 s versus 3.03 s for 14 separate traces (ran it).
- (8) **Silent-failure bug in 0.7.0:** when invoke inputs are pre-tokenized `torch.Tensor`s, every invoke after the first gets an all-zero attention mask. Even with no intervention at all, a second invoke of the identical prompt returned logits 16.9 away from the clean run, and 14 head-ablation invokes gave errors of 16 to 18 logits for rows 1 to 13 (ran it). Root cause: `LanguageModel._tokenize()` wraps a tensor as `BatchEncoding({"input_ids": inputs})` with no mask (`$SP/nnsight/modeling/language.py:236-239`). `_batch()` defaults a ones-mask only for the first invoke and leaves `combined_mask` rows zero when `new_attention_mask` is None (`language.py:380-416`) (code-verified). Strings, lists of ints, and dicts carrying `attention_mask` are all exact (mad 0.0) (ran it). 0.8.0rc1 fixes it: `_encode_pretokenized` uses `torch.ones_like(input_ids)` when no mask is given (`nnsight-0.8.0rc1` wheel, `nnsight/modeling/transformers.py:1240-1268`) (code-verified).
- (9) Resume-from-depth: `model.model.layers[j].skip(cached_resid[j+1][None])` for j < 12, followed by a normal run of layers 12 to 23, gave logits identical to the full forward (mad 0.0) in 0.130 s versus 0.188 s (ran it).
- (10) Attention probabilities: `self_attn.output[1]` gives `[1, 14, 5, 5]` under eager attention (ran it).
- (11) Subject and reporter as the same model (a Patchscope-style self-report): within one `model.session()`, a `trace` on the subject prompt read the layer-6 residual at "France". A `generate` on the reporter prompt "Repeat the word: x x x. The word is" then wrote it into the first " x" position only at decode step 0 (`for step in tracer.iter[0]`). The model produced " repeated three times. France France" (unmodified: ' "x x x". The'). The token IDs equal a NeuralScope-style loop whose edit fires only when absolute position 4 is processed. The whole session took 1.00 s (ran it).
- (12) `remote="local"` (serialize, deserialize and execute in-process with non-installed modules hidden) worked and returned " Paris" (ran it).
- Trace semantics that bit me (ran it plus code-verified): (a) At the root trace only objects registered through `.save()` are pushed back to the caller's frame (`id(v) in Globals.saves` in `Tracer.push`, `$SP/nnsight/intervention/tracing/base.py:514-575`). So `hs = [l.output.save() for l in ...]` leaves `hs` undefined, while `nnsight.save([...])` or appending to an outer list works. (b) Within one invoke, accesses must follow forward-execution order: reading `layers_output[10]` before layer 10's attention probabilities raised `MissedProviderError ... Did you call an Envoy out of order?`.

**Source-code capture constraint (the prior "OSError: could not get source code")**
- nnsight 0.5 and later compile the body of the `with` block from its source text. `Tracer.capture` handles four cases: a nested trace, IPython/Jupyter (`_ih`), a regular file via `inspect.getsourcelines(frame)`, and `python -c` (recovered from `sys.orig_argv`) (`$SP/nnsight/intervention/tracing/base.py:240-360`) (code-verified). Documentation: "Anything with no reachable source — a raw `exec` string, a heredoc, `<stdin>` — yields empty text ... Write snippets to a real `.py` file" ([NNsight.md](https://github.com/ndif-team/nnsight/blob/main/NNsight.md)) (docs).
- Results for the same tiny script in seven contexts (ran it): `python file.py` works. `python -c "..."` works. `exec(compile(src, fn, 'exec'))` works after registering `src` in `linecache.cache[fn]`. `runpy.run_path(tempfile)` works. `python - < file.py` (stdin) fails with `OSError: could not get source code`. `exec(compile(src, '<string>', 'exec'))` inside a `.py` file fails with the same `OSError`. The same inside `python -c` fails with `WithBlockNotFoundError` (nnsight parses the outer `-c` program instead).

### Inferences
- NeuralScope's `hf_decoder.py` hook plumbing (the capture hooks, the o_proj pre-hook head edits, MLP and residual edits, the batched `_Session`, and the resume-from-depth forward) can be expressed in nnsight with identical numerics and equal speed. That makes nnsight a drop-in backend for a thin adapter that keeps NeuralScope's `Edit` vocabulary (inference, based on items 2, 3, 7 and 9 above and the sweep benchmark in §9).
- If NeuralScope adopts 0.7.0, the adapter must never pass raw tensors to multi-invoke traces; pass lists or a dict with `attention_mask`, or pin 0.8.x once it is final. It must also pass `repetition_penalty=1.0` (or build its own greedy loop) for reproducible greedy decoding (inference, from items 6 and 8).
- For SelfLab, the source-capture rule means that model-authored or dynamically generated experiment code must be written to a file (or registered in `linecache`) before tracing. It also means nnsight cannot execute a declarative spec without a code-generation step (inference, from the source-capture results). Remote untrusted execution on NDIF is process-isolated but explicitly not hardened (docs).
- NDIF is useful to SelfLab only for larger models: Llama-3.1/3.3 at 8B to 405B, Gemma-2, and Qwen2.5 at 7B to 72B are HOT. The mission's small Qwen2.5 models are COLD there and run fine locally (inference).

### Gaps
- NDIF was not exercised end-to-end: no API key was available, so remote gradients, remote `generate` with `iter`, and the public service's actual time limit and queue latency are unverified. It is also not confirmed whether COLD models can be requested on demand by ordinary users.
- 0.8.0rc1 was only code-inspected (the batching fix), not run. Its other changes ("the 0.8 pipeline rewrite") are unaudited.
- The nnsight vLLM path was not run (CPU-only machine).

## 2. TransformerLens: the 4.0 TransformerBridge versus the 3.x line (HookedTransformer)

### Takeaway
TransformerLens 4.0.0 (2026-09-21) removed `HookedTransformer`. `from transformer_lens import HookedTransformer` now fails with ImportError, and the correct 4.x API is `TransformerBridge.boot_transformers(name)`, optionally followed by `enable_compatibility_mode()`. The bridge wraps the real HF module (eager attention forced). On Qwen2.5-0.5B-Instruct its logits, residuals, hook_z head ablation, residual patching and gradients were bit-exact against HF, and its greedy steered generation matches pure argmax. It lacks a compute-saving resume: `start_at_layer` still runs the earlier blocks. Its `patching.get_act_patch_*` utilities do one forward per cell, about 6x slower than NeuralScope's batched sweep here. 4.0 also breaks SAELens (and circuit-tracer's TL backend), which still require TL < 4. The 3.x line (3.9.0, 2026-09-12) ships both APIs.

### Cited Findings
- Identity: PyPI `transformer-lens` 4.0.0 (2026-09-21), MIT, repo github.com/TransformerLensOrg/TransformerLens (last commit 2026-09-28). 4.0 requires `transformers>=5.9.0` and `torch>=2.6`. A parallel 3.x line continues (3.7.x to 3.9.0, 2026-08-07 to 09-12; 4.0.0b1 2026-07-21) ([PyPI JSON](https://pypi.org/pypi/transformer-lens/json)) (docs). There is no dedicated library paper; the original author is Neel Nanda (PyPI author field) (docs).
- Removal and migration: `$SP/transformer_lens/__init__.py` defines `_REMOVED_IN_4_0`, including "HookedTransformer": "Use TransformerBridge.boot_transformers(name), then enable_compatibility_mode() for HookedTransformer-equivalent numerics" (code-verified). With `from transformer_lens import HookedTransformer` that pointer is lost and a bare `ImportError: cannot import name 'HookedTransformer'` is raised (ran it). This is tracked upstream as [TL #1801](https://github.com/TransformerLensOrg/TransformerLens/issues/1801) with fix PR [#1802](https://github.com/TransformerLensOrg/TransformerLens/pull/1802) (docs).
- `boot_transformers(model_name, hf_config_overrides, device, dtype, tokenizer, load_weights, trust_remote_code, model_class, hf_model, n_ctx, revision, device_map, ...)`. Its docstring: "Returns raw HF weights by default — logits/activations match HF, not legacy HookedTransformer ... Attention implementation is forced to 'eager'" (`$SP/transformer_lens/model_bridge/sources/transformers/source.py:41-80`) (code-verified). `hf_model=` lets the bridge share an already-loaded HF model object (code-verified).
- Hooks on Qwen2.5-0.5B: 1,383 hook points (ran it). Per block they include `hook_resid_pre`, `hook_resid_mid`, `hook_resid_post`, `hook_attn_in`, `hook_attn_out`, `hook_mlp_in`, `hook_mlp_out`, `attn.hook_q/k/v`, `attn.hook_rot_q/rot_k`, `attn.hook_attn_scores`, `attn.hook_pattern`, `attn.hook_z`, `attn.hook_result`, `mlp.hook_pre`, `mlp.hook_pre_linear`, `mlp.hook_post`, `ln1/ln2.hook_scale/hook_normalized`, and submodule `hook_in/hook_out` (ran it). Shapes: `hook_z` [1,5,14,64], `hook_pattern` [1,14,5,5], `hook_attn_out`/`hook_mlp_out`/`hook_resid_mid` [1,5,896]. `attn.hook_result` is registered but was not populated by a default `run_with_cache` (KeyError) (ran it).
- Exactness in default (raw) mode (ran it, `$W/test_tlens.py`, results in `$W/test_tlens_results.json`):
  - `run_with_cache`: logits bit-identical to HF eager (mad 0.0), residuals exact (0.0), 0.237 s.
  - `run_with_hooks` zeroing `z[:, :, 3, :]` at `blocks.10.attn.hook_z`: mad 0.0, 0.211 s.

### Inferences
- For NeuralScope, TL 4.0 is a sound, exact reading and writing substrate with a rich named-hook vocabulary. ## 3. interp-engine (decoderesearch / Neuronpedia), version 1.12.0: identity and capabilities

### Takeaway
"interp-engine" is a single, unambiguous project: Neuronpedia's inference engine, PyPI `interp-engine` 1.12.0 (2026-09-28), Apache-2.0, github.com/decoderesearch/interp-engine. It has 34 standardized hook "points" (27 core plus 7 for DeepSeek-V4-style hyper-connection streams), an eager HF backend and three vLLM backends. Its features include steering (additive, orthogonal, projection-cap), a logit lens, a Jacobian-lens read-out and interventions (vLLM worker side), eager-only gradients, and a cross-engine validator against TransformerLens and nnsight (README: "50+ models"; the committed results cover 37 checkpoints). On Qwen2.5-0.5B-Instruct the eager backend was bit-exact on every check: residuals, z, attention probabilities, logits, logit lens, head ablation, patching, gradients, and greedy steered generation. It has no batched-intervention or resume primitives beyond plain batching, and its first-class write API is steering. Arbitrary edits go through a low-level `HookManager`.

### Cited Findings

  - Summary: "A fast, standardized, and easy to use interpretability engine."

### Inferences
- interp-engine is the best-engineered candidate for standardized, exact reading and steering across many architectures, and its refusal-over-silent-failure design suits autonomous or agent-driven use. But its public write vocabulary is steering-shaped. Head scaling, mean/resample set-z, residual set, batched edit sets and resume-from-depth would all need NeuralScope-side code on top of `HookManager.write` (inference, from the API survey and hands-on).
- Its vLLM backends are the only audited route to high-throughput capture and steering on a GPU (for example the many generations SelfLab calibration studies need). They forgo gradients and exact per-token numerics, which matters when interventions and self-reports must be compared at small effect sizes (inference, from the validator worst-token cosines and GRADIENTS.md).

### Gaps
- vLLM backends and `vllm-static` were not run (no GPU). Jacobian-lens read-out on eager with a fitted transport was not run. There is no paper; the release date and announcement text could not be confirmed from a primary page.

## 4. nnterp 1.3.0: standardized interface on NNsight

### Takeaway
nnterp is a thin renaming and validation layer over nnsight, now under the NDIF GitHub org. It gives architecture-independent accessors (`layers_output[i]`, `attentions_output[i]`, `mlps_output[i]`, `attention_probabilities[i]`) plus built-in logit lens, Patchscope lens/generate, steering and layer skipping. It was exact on Qwen2.5-0.5B-Instruct. It adds no batching or resume primitive beyond nnsight's, has no per-head z accessor, and inherits nnsight's constraints.

### Cited Findings
- Identity: PyPI `nnterp` 1.3.0 (2026-02-28), MIT, author Clément Dumas, `requires nnsight>=0.6` ([PyPI JSON](https://pypi.org/pypi/nnterp/json)) (docs). Repos github.com/ndif-team/nnterp (last commit 2026-07-02) and github.com/Butanium/nnterp (ran it: shallow-clone metadata; the search result lists both). Paper: "nnterp: A Standardized Interface for Mechanistic Interpretability of Transformers", arXiv [2511.14465](https://arxiv.org/abs/2511.14465), NeurIPS 2025 Mechanistic Interpretability workshop. It claims "50+ model variants spanning 16 architecture families" (paper).
- API (code-verified, `$SP/nnterp/standardized_transformer.py:35-374`, `interventions.py`):
  - `StandardizedTransformer(model, trust_remote_code, check_renaming=True, remote=False, allow_dispatch=True, enable_attention_probs=False, check_attn_probs_with_trace=True, rename_config=None, **kwargs)`.
  - Accessors `layers_input/output`, `attentions_input/output`, `mlps_input/output`, `token_embeddings`, `logits`, `next_token_probs`, `attention_probabilities`; methods `skip_layer(s)`, `steer(layers, steering_vector, factor=1, positions=None, ...)`, `project_on_vocab`, `get_topk_closest_tokens`.
  - Interventions: `logit_lens`, `patchscope_lens`, `patchscope_generate`, `patch_object_attn_lens`, `repeat_prompt`, `it_repeat_prompt`, `TargetPrompt(Batch)`.

### Inferences
- nnterp could replace NeuralScope's model-family plumbing (`SUPPORTED_MODEL_TYPES`, direct `model.model.layers` access) and its logit lens, and adds Patchscope-style generation, a natural primitive for SelfLab self-report experiments. NeuralScope's head-level edits would still need raw nnsight access to `self_attn.o_proj.input` (inference).

### Gaps
- `patchscope_generate` and `steer` were code-read, not run. The 1.3.0 release versus the unreleased main-branch changes (commits to 2026-07-02) were not diffed.

## 5. pyvene 0.1.8 (Stanford): interchange and trainable interventions

### Takeaway
pyvene's declarative `IntervenableConfig` covers interchange interventions (activation patching), collection, zero, addition and noise interventions, and trainable interventions (DAS-style rotated subspaces, low-rank, masks, autoencoders), with generation under interventions. Its Qwen2 mapping hooks the same head-z site as NeuralScope. Block-level interchange and collection are exact under transformers 5.17. But the last PyPI release (0.1.8) is from May 2025. Head-level components crash on transformers 5.x (`Qwen2Config` has no `head_dim`; fixed on main 2026-03-05, unreleased), and there are no Qwen3 or Gemma-3 mappings.

### Cited Findings

- Hands-on with transformers 5.17 (ran it, `$W/test_pyvene.py`, `test_pyvene2.py`):

### Inferences
- pyvene's distinctive value for SelfLab is trainable interventions: DAS/distributed alignment search to find a subspace whose interchange changes a self-report. Neither nnsight, TL nor interp-engine packages these. As a general backend it is stale for transformers 5.x and the newer model families (inference).

### Gaps
- pyvene's main branch (with the head_dim fix) was not installed. Behaviour on Qwen3 and Gemma-3 via custom component paths is untested.

## 7. circuit-tracer: attribution graphs with transcoders

### Takeaway
circuit-tracer (Anthropic Fellows' Hanna and Piotrowski, with Decode Research) computes attribution graphs over transcoder features and supports feature interventions, including during generation. The official repo (safety-research/circuit-tracer) is install-from-source. The PyPI package `circuit-tracer` 0.5.0 is a third-party fork (Caerii). Both pin transformers ≤ 4.57.3, so neither runs in NeuralScope's transformers-5.17 environment. There are no transcoders for Qwen2.5; supported models are Gemma-2-2B, Llama-3.2-1B, Qwen3 0.6B to 14B, Gemma-3 270M to 27B (nnsight backend) and Llama-3.1-8B-Instruct.

### Cited Findings
- Official repo safety-research/circuit-tracer: last commit 2026-09-11, "Port the nnsight backend to nnsight 0.8 (#113)". `pyproject.toml` requires `nnsight>=0.8.0rc1,<0.9`, `transformer-lens>=2.16.0`, `transformers>=4.56.0,<=4.57.3`, with a dynamic version. The README says: "To install this library, clone it and run the command `pip install .`". LICENSE: "Copyright (c) 2024 Michael Hanna and Mateusz Piotrowski" (MIT text) (`$W/repos/circuit-tracer/`) (code-verified).

Requires `transformers<=4.57.3,>=4.56.0`, `nnsight>=0.6.0`, `transformer-lens>=2.16.0` ([PyPI JSON](https://pypi.org/pypi/circuit-tracer/json)) (docs). The fork's last commit is 2026-08-03 (ran it: shallow-clone metadata).

## 8. Other 2025–2026 frameworks, and whether anything supersedes the above

### Takeaway
No new 2026 library supersedes nnsight or TransformerLens as the activation and intervention substrate. The 2026 additions are interp-engine (§3), the TL 4.0 bridge rewrite (§2), nnsight 0.6 to 0.8 (§1), orchestration or circuit layers built on these (Interpreto, MURANO, CircuitKIT, interpretune), NDIF-like remote fabrics (eDIF), and the Jacobian lens (Anthropic, July 2026). The J-lens is now implemented in TL 4.0 and interp-engine, with pre-fitted artifacts for many open models but not for Qwen2.5-0.5B/1.5B. It is directly relevant to SelfLab because the originating paper tests introspective detection of injected concepts.

### Cited Findings
- Jacobian lens: "Verbalizable Representations Form a Global Workspace in Language Models", 2026-07-06, Gurnee, Sofroniew, ... Lindsey ([transformer-circuits.pub/2026/workspace](https://transformer-circuits.pub/2026/workspace/)) (paper).
  - Definition: "J_ℓ = E[∂h_final,t'/∂h_ℓ,t]" averaged over source and subsequent positions and "a corpus of one thousand prompts".
  - It studies Claude models and tests steering "h ← h + α v_t", concept swaps, and "introspective detection of an injected concept" (paper).
  - Artifacts: huggingface.co/neuronpedia/jacobian-lens (MIT, last modified 2026-09-25) has fitted `*_jacobian_lens.pt` for qwen2.5-7b-it, qwen3-{1.7b,4b,8b,14b,32b}, qwen3.5-{0.8b,2b,4b,27b,...}, gemma-2/3/4 variants, llama3.1-8b(-it), llama3.3-70b-it, gpt2-small, pythia-70m, olmo-3, gpt-oss-20b and deepseek-v4-flash. None exist for Qwen2.5-0.5B/1.5B (ran it: HF API listing).
  - Implementations: TL 4.0 `JacobianLens` (fit, readout, steering, ablation and swap hooks) and interp-engine's vLLM J-lens interventions (§2, §3) (code-verified).
- Interpreto (arXiv [2512.09730](https://arxiv.org/abs/2512.09730)): attribution and concept-based explanations; "wraps nnsight" (docs, search summary). MURANO (arXiv [2608.30662](https://arxiv.org/abs/2608.30662), EMNLP 2026): "builds on existing interpretability and machine learning libraries", composing loading, recording, attribution, intervention and evaluation steps (paper abstract). CircuitKIT (arXiv [2607.19317](https://arxiv.org/abs/2607.19317), github.com/Lexsi-Labs/CircuitKIT): circuit discovery and evaluation (paper abstract). eDIF (arXiv [2508.10553](https://arxiv.org/abs/2508.10553)): a European deep inference fabric for remote interpretability (docs, search result). None were code-audited.
- Stale or adjacent packages (PyPI JSON, ran it): tuned-lens 0.2.0 (2023-07-18, older information); penzai 0.2.5 (2025-04-08, JAX); inseq 0.7.1 (2026-03-06, attribution); steering-vectors 0.12.2 (2025-02-21); repeng 0.4.0 (2024-12-14); dictionary-learning 0.1.0 (2025-02-12); `baukit` is not on PyPI.

### Inferences
- For a small team, the pragmatic 2026 stack is nnsight (or nnterp) for exact HF-native interventions and remote access, interp-engine for standardized points and vLLM throughput, TL 4.0 only if its analysis tools (attribution patching, J-lens fit) are wanted, and pyvene only for trainable interventions (inference).

### Gaps
- MURANO's and CircuitKIT's backends, model coverage and code quality are unknown (only abstracts read). The Interpreto claim comes from a search summary.

## 9. Capability-by-capability map against NeuralScope, sweep benchmark, and fitness as a SelfLab backend

### Takeaway
Every NeuralScope instrumentation primitive has an exact external equivalent. The two sweep accelerations (batched edit sets plus resume-from-depth) are fully reproducible only in nnsight (batch plus `.skip()`), which matched NeuralScope's timings and numbers exactly. TransformerLens and interp-engine reach only plain batching, and TL's packaged patching utility is about 6x slower. What NeuralScope has that none of the libraries package is: a declarative, validated edit vocabulary with absolute-position semantics across KV-cached decoding; sweep orchestration with resume; OBSERVED/DERIVED epistemic labelling; exact frozen-norm DLA that sums to the logit; and persistent trace storage (SQLite plus safetensors). Everything below the edit vocabulary (hooks, model-family plumbing, the capture loop) is replaceable.

- Gradients (NeuralScope capability flag `"gradients": False`, `hf_decoder.py:191`): nnsight backward (0.0), TL `bwd_hooks` (0.0) + `attribution_patch` (code-verified), interp-engine eager `requires_grad=True` (0.0), pyvene trainable interventions.
- Model coverage beyond qwen2/llama/mistral (NeuralScope refuses Gemma: "Gemma needs (1+w) RMSNorm, embedding scaling and logit soft-capping", `hf_decoder.py:135-139`): nnsight, nnterp and interp-engine run the real HF modules; TL has gemma2/gemma3/qwen3 adapters; all were validated on Gemma-2/3 and Qwen3 by the interp-engine validator (code-verified, repo data).

**SelfLab backend fitness (subject = reporter, injection, batching, generation, gradients, remote)**
- Same model as subject and reporter, with activation injection into a reporter prompt during generation: nnsight session, token-identical to a NeuralScope-style loop (ran it, §1 item 11). nnterp provides `patchscope_lens`/`patchscope_generate` (code-verified). TL, interp-engine and pyvene can do it with hooks or interchange (pyvene's source→base interchange ran exact) (inference for TL and interp-engine in generation).
- Remote execution for large models: only nnsight/NDIF (plus self-hosted NDIF and eDIF) (docs). interp-engine's vLLM path is self-hosted throughput, not a shared service (docs).
- Bounded, read-only experiments run by the model on itself:
  - nnsight executes Python source (a file or linecache is required) and NDIF's sandbox is "not hardened" (docs).
  - pyvene's `IntervenableConfig`, interp-engine's `SteeringSpec`/`Address` and NeuralScope's compiled `Edit` dataclasses are the only declarative intervention specs among those audited (code-verified). interp-engine's policy of raising on any unsupported argument ("Never a warning and never a silent no-op", `$SP/interp_engine/__init__.py` comments; `dispatch.py`) is the only systematic guard against silently unaffected results (code-verified).

### Inferences
- **Delete or replace with a thin adapter:** the native-hook machinery in `hf_decoder.py` (capture hooks, the o_proj pre-hook head edits, MLP and residual hooks, `SUPPORTED_MODEL_TYPES`, the manual rotary/mask construction in the resume path). An nnsight-based adapter (or nnterp for naming) reproduces it exactly, including resume via `.skip()`, and extends coverage to Gemma-2/3 and Qwen3 and adds gradients. The logit-lens computation can delegate to `decode_residuals` (interp-engine) or `project_on_vocab` (nnterp) (inference).
- **Keep:** the `Edit` vocabulary as SelfLab's declarative, validatable intervention language, since model-proposed experiments should be data, not code; absolute-position edit semantics across KV-cached greedy decoding, with an explicit `repetition_penalty=1.0` or own loop for determinism; the sweep orchestration with batch plus resume; DLA with the frozen norm scale and exact-sum test; OBSERVED/DERIVED status labels; and the SQLite/safetensors trace store. No audited library provides these (inference).
- **Add from libraries rather than build:** attribution patching (TL 4.0 `attribution_patch` or nnsight backward), J-lens read-out and steering (TL `JacobianLens`, fitting locally for Qwen2.5 since no artifact exists), trainable subspace interventions (pyvene), SAEs and transcoders only on models that have them (SAELens/circuit-tracer on Qwen3, Gemma or Llama), and NDIF for any 7B+ replication (inference).
- Missing everywhere, and therefore SelfLab's own contribution: a counterfactual self-prediction harness (elicit the model's prediction of an intervention's effect, run the intervention, score calibration); a registry linking self-reports to the exact causal runs that test them; budgets and permissions for model-initiated read-only experiments; and cross-run comparability guarantees (fixed decoding config, dtype, attention kernel) (inference).

### Gaps
- The benchmark uses one short prompt (5 tokens) on CPU. Relative costs will differ on GPU and for long contexts (resume savings scale with the skipped fraction). TL's DLA and attribution-patching outputs were not numerically compared with NeuralScope's DLA.
